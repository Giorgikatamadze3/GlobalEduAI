# GlobalEdu

ქართულენოვანი საერთაშორისო განათლების პლატფორმა: უნივერსიტეტების დირექტორია, ოფიციალური პროგრამები, პირობებზე დაფუძნებული შერჩევა და აპლიკანტის პირადი სივრცე.

## GitHub და Vercel

საწყისი კოდი ინახება [GlobalEduAI რეპოზიტორიაში](https://github.com/Giorgikatamadze3/GlobalEduAI). პროექტი გამზადებულია Vercel-ის Express ჰოსტინგისთვის: `npm run build` ქმნის მხოლოდ საჯარო ფაილებს, ანგარიშები კი ღრუბელში PostgreSQL-ში ინახება. GitHub-ის HTML ფაილის პირდაპირ გახსნა API-ს ვერ გაუშვებს; მეგობრებისთვის საჭიროა Vercel-ის ვებსაიტის ბმული. [გამოქვეყნება და ბაზის გამართვა](docs/DEPLOYMENT.md).

## Localhost

პროექტის ძირეულ საქაღალდეში:

```powershell
npm.cmd install
npm.cmd start
```

საჭიროა **Node.js 24**. ლოკალურად ანგარიშები შეიძლება ინახებოდეს ჩაშენებულ SQLite-ში; Vercel-ზე გამოიყენება მუდმივი PostgreSQL საცავი.

გახსენით **http://localhost:3000/#universities**. უკვე გაშვებული ძველი Node სერვერი გადატვირთეთ, რათა ჩაიტვირთოს ახალი API და მონაცემები. PowerShell-ში გამოიყენეთ `npm.cmd`, თუ `npm.ps1` execution policy-ით შეზღუდულია.

`npm.cmd run dev` — განვითარება; `npm.cmd run check` — სინტაქსი და მონაცემთა ვალიდაცია; `npm.cmd test` — ლოგიკისა და API-ის ტესტები.

უნივერსიტეტების კატალოგსა და ანგარიშებს **MongoDB და API გასაღები არ სჭირდება**. რეგისტრაცია, ავტორიზაცია და ფავორიტები მუშაობს ლოკალურ SQLite ბაზაში. `PORT` არასავალდებულოა, ნაგულისხმევია `3000`. ელფოსტის არსებული API იყენებს `EMAIL_USER`/`EMAIL_PASS`-ს; მისი კონფიგურაცია ანგარიშებისთვის საჭირო არ არის. სერვერი MongoDB-სთან დაკავშირებას გაშვებისას აღარ ცდილობს.

კაბინეტის დემო: **http://localhost:3000/?preview=1#dashboard**. ეს მხოლოდ ანგარიშის დემოა — უნივერსიტეტების კატალოგი რეალურ წყაროებზე რჩება. დემოს ავტორიზაცია მუდმივ ანგარიშს არ ქმნის; დემოს ფავორიტები რეალური ანგარიშისგან გამოყოფილია. რეალური ანგარიშის შესაქმნელად გახსენით საიტი `?preview=1`-ის გარეშე.

## ანგარიშები და ავტორიზაცია

პირველ გაშვებაზე სერვერი ქმნის ანგარიშების SQLite ფაილსა და სქემას. სურვილის შემთხვევაში მხოლოდ ბაზის ინიციალიზაცია შეიძლება სერვერის გაშვების გარეშეც:

```powershell
npm.cmd run auth:init
```

კონფიგურაციის ნიმუშია `Server/.env.example`. არსებული `Server/.env` ფაილი ავტომატურად არ გადაიწერება.

```dotenv
AUTH_DB_DRIVER=sqlite
AUTH_DB_PATH=data/accounts.sqlite
```

`AUTH_DB_PATH`-ის ფარდობითი მისამართი ითვლება `Server/` საქაღალდიდან; შესაძლებელია აბსოლუტური მისამართიც. ნაგულისხმევი ფაილია `Server/data/accounts.sqlite`. ბაზა და მისი WAL/SHM ფაილები Git-ში არ იტვირთება და საჯარო სტატიკურ რესურსებად არ გაიცემა. ანგარიშები სერვერის გადატვირთვის შემდეგ რჩება. სხვა დრაივერი აშკარა შეცდომას გამოიწვევს; ჩუმი სათადარიგო საცავი არ გამოიყენება. `:memory:` გამოიყენება მხოლოდ ტესტებისა და დროებითი სერვერისთვის.

- **სტუდენტი:** პირადი პროფილი, განათლების საფეხური, მოქალაქეობა, დასრულების წელი და ფავორიტები.
- **მრჩეველი:** ორგანიზაცია/პრაქტიკა, პოზიცია, ვებსაიტი, აღწერა და საკონსულტაციო მიმართულებები. ახალი მრჩეველის გადამოწმების სტატუსია `pending`; რეგისტრაცია დადასტურებულ ექსპერტობას არ ნიშნავს.
- როლი რეგისტრაციისას ირჩევა და პროფილის API-დან ვერ იცვლება. როლების პროფილებს ცალკე წვდომის შემოწმება აქვს.
- პაროლები ინახება ჰეშით. ბრაუზერი იღებს `HttpOnly`, `SameSite=Lax` სესიის ქუქის; JWT ან სესიის ტოკენი `localStorage`-ში არ ინახება. ბაზაში მხოლოდ სესიის SHA-256 ჰეშია.
- ჩვეულებრივი სესიის ვადაა **12 საათი**, „დამიმახსოვრე“ არჩევით — **30 დღე**. გასვლა სესიას სერვერზე აუქმებს.
- სერვერი ინახავს წესებზე თანხმობის დროსა და ვერსიას; ეს ველები პროფილის მოთხოვნით ვერ გადაიწერება.

გახსენით **http://localhost:3000/#register**, შეარჩიეთ ანგარიშის ტიპი და შექმენით ანგარიში. ნამდვილ რეგისტრაციას მუშაობისთვის ელფოსტის გაგზავნა არ სჭირდება. ავტორიზაციაზე მოქმედებს მცდელობების ლიმიტი და ველების სერვერული ვალიდაცია.

რეკომენდებული ლოკალური გაშვება ერთ მისამართზეა — `http://localhost:3000`. განვითარებისას ნებადართულია იმავე origin-იდან და localhost/127.0.0.1-ის კონკრეტული პორტებიდან (`3000`, `5500`, `5501`, `5173`, `4173`, მიმდინარე სერვერის პორტი) ქუქით მოთხოვნები. უცხო origin-ებს ანგარიშის ცვლილება არ შეუძლიათ. Production რეჟიმში ქუქი `Secure`-ია და საჭიროა HTTPS.

## კატალოგის მოცულობა

2026-10-27-ის სურათი შეიცავს:

- **10,268 დაწესებულებას, 200 ქვეყნისა და ტერიტორიის კოდით**, Hipo-ის MIT-ლიცენზირებული დირექტორიიდან.
- **20 კონკრეტულ პროგრამას, 16 უნივერსიტეტში, 9 ქვეყანაში**, უნივერსიტეტების ოფიციალური პროგრამის/მიღების გვერდებით.
- ყოველ პროგრამაზე წყაროებს, შემოწმების თარიღს, საფასურის ვალუტას/პერიოდს/აპლიკანტის კატეგორიას და ცნობილ მოთხოვნებს.

დირექტორიაში შედის უნივერსიტეტები, კოლეჯები და სხვა ჩამოთვლილი დაწესებულებები. **ეს არ არის მსოფლიოს ყველა უნივერსიტეტის სრული სია ან აკრედიტაციის რეესტრი.** სახელისა და ვებსაიტის არსებობა კონკრეტულ პროგრამას, ფასს, მიღების უფლებას ან სტიპენდიას არ ადასტურებს.

საიტს აქვს ორი დაკავშირებული ხედი:

1. **უნივერსიტეტების დირექტორია** — ქვეყანა, რეგიონი, სახელი, დომენი, საიტი და ჩვენთან აღწერილი პროგრამები.
2. **პროგრამები და პირობები** — კონკრეტული საფეხური, მიმართულება, ენა, რეჟიმი და წყაროთი აღწერილი ფინანსური/სააპლიკაციო პირობები.

უცნობი მნიშვნელობები ინახება `null`-ად. ფასი არასოდეს გენერირდება შემთხვევით; უცნობი თანხა ნულს არ უდრის. სტიპენდია არ მიებმება უნივერსიტეტს მხოლოდ ქვეყნის მიხედვით. ძველი სინთეზური MongoDB კოლექცია საჯარო კატალოგში აღარ იკითხება და არ იშლება.

## მრჩეველი

გაფართოებული ფილტრი საშუალებას იძლევა ერთდროულად აირჩიოთ რამდენიმე ქვეყანა, რეგიონი, მიმართულება, სპეციალიზაცია, საფეხური, ენა და ფორმატი. დამატებულია ხანგრძლივობა, მიღების ციკლი, თარიღების დიაპაზონი, ცნობილი/ნულოვანი საფასური, დაფინანსება და მონაცემების სისრულე. პროგრამული ფილტრაცია უნივერსიტეტებს არჩევს მხოლოდ დაკავშირებული, აღწერილი პროგრამებით.

ინტერესებისა და აკადემიური პროფილის მიხედვით გამოითვლება **0–100 შესაბამისობის ქულა**, მონაცემების დაფარვა და ყველა მოთხოვნიდან დადასტურებული ქულა. პრიორიტეტები რეგულირდება; შედეგები შეიძლება დალაგდეს ქულით. სტუდენტს შეუძლია პროფილის შენახვა ამ ბრაუზერში. ისტორიული მიღების ოფიციალური მაჩვენებელი ნაჩვენებია იქ, სადაც შესაბამისი კოჰორტა წყაროთი დასტურდება; ეს პირადი მიღების ალბათობად არ გარდაიქმნება. [ფორმულები და წყაროები](docs/SCORING.md).

`catalog-core.js` ერთსა და იმავე წესებს იყენებს ბრაუზერსა და სერვერზე. შედეგები იყოფა:

- `matches` — ცნობილი, შემოწმებადი პირობები ემთხვევა.
- `needs-verification` — შესაბამისობის გასამყარებლად მონაცემი ან აპლიკანტის გარემოება დასაზუსტებელია.
- `excluded` — ცნობილი მონაცემი პირდაპირ ეწინააღმდეგება მოთხოვნას; მიზეზი ნაჩვენებია.

ფილტრები ითვალისწინებს ქვეყანას/რეგიონს, საფეხურს, მიმართულებას, ენას, ფორმატს, GPA-ს პროცენტულ სკალას, ენის ტესტსა და კომპონენტებს, გამოცდილებას, მოქალაქეობაზე გამოქვეყნებულ შეზღუდვებს, ბიუჯეტს, ვადებსა და წყაროს სიახლეს.

ვალუტა არ გადაითვლება. პროგრამის სრული საფასური წლიურ ფასად არ იყოფა ავტომატურად. სწავლის ნულოვანი საფასური არ ნიშნავს ცხოვრების ხარჯების დაფინანსებას. მოქალაქეობა მარტო არ ადგენს ბინადრობას, შეღავათს ან სტიპენდიის უფლებას. მოძველებული ან არასრული წყარო არ ნიშნავს დადასტურებულ შესაბამისობას. თუ შედეგი არ არის, სხვა შემთხვევითი პროგრამები არ ჩანაცვლდება.

მრჩეველს აქვს ორი ჩანართი: **პროფილის შეფასება** გამჭვირვალე წესებით ადარებს პროგრამების პირობებს; **ესაუბრე AI-ს** ცალკე სასაუბრო აგენტს უკავშირდება. აგენტი კატალოგში ძიებას, პროგრამის დეტალებსა და შეფასებას იყენებს. ფართო დირექტორიის დაუზუსტებელი პროგრამები „შესაბამისად“ არ ითვლება და მიღების პირადი ალბათობა არ გამოიგონება.

სასაუბრო აგენტის გასააქტიურებლად `Server/.env`-ში ადგილობრივად დაამატეთ `OPENAI_API_KEY` და გადატვირთეთ სერვერი. სურვილისამებრ მიუთითეთ `OPENAI_MODEL` (ნაგულისხმევია `gpt-5.4-mini`). გასაღები ბრაუზერში არ გაიცემა. გასაღების გარეშე ჩატი მიუწვდომლობას აჩვენებს; პროფილის შეფასება ჩვეულებრივ მუშაობს. [AI აგენტის გამართვა და შეზღუდვები](docs/AI-ADVISOR.md).

## განახლება და იმპორტი

```powershell
npm.cmd run catalog:sync
npm.cmd run catalog:check
npm.cmd run catalog:import
```

`catalog:sync` ჩამოტვირთავს Hipo-ის გამოქვეყნებულ დირექტორიასა და MIT ლიცენზიას; ამოწმებს URL-ებს, სტაბილურ ID-ებს, დუბლიკატებს და მოულოდნელ შემცირებას. ვალიდური ფაილი ატომურად იცვლება. შემდეგ გადატვირთეთ სერვერი.

`catalog:import` ნაგულისხმევად **მხოლოდ მშრალი შემოწმებაა**: MongoDB-ს არ უკავშირდება. სურვილის შემთხვევაში:

```powershell
node Server/seed.js --export Server/data/catalog-export.json
node Server/seed.js --write
```

`--write` ცხადად ითხოვს MongoDB-ში `institutions` და `studyprograms` კოლექციების განახლებას სტაბილური ID-ებით. არ ხდება კოლექციის გასუფთავება, წაშლა ან ძველი შემთხვევითი ჩანაწერების დამატება რეალურ მონაცემებში. ამ სამუშაოს ფარგლებში რეალურ ბაზაში იმპორტი არ შესრულებულა.

ახალი პროგრამის დასამატებლად განაახლეთ `Server/data/programs.json` ოფიციალური წყაროებით, მეტამონაცემების რაოდენობა და შემოწმების თარიღები; გაურკვეველი ფაქტები დატოვეთ `null`-ად. `catalog:check` და `npm.cmd test` ამოწმებს მონაცემებსა და მოთხოვნების ლოგიკას. უნივერსიტეტის დომენით კავშირი უნდა იყოს ერთმნიშვნელოვანი; დაუკავშირებელი პროგრამა სერვერის ჩატვირთვისას არ მიიღება.

წყაროები: [დირექტორიის წარმოშობა და განახლება](docs/UNIVERSITY-DATA-SOURCES.md), [პროგრამების ოფიციალური წყაროები](docs/program-sources.md), [Hipo MIT ლიცენზია](docs/third-party/HIPO-LICENSE.txt).

## API

| მარშრუტი | დანიშნულება |
| --- | --- |
| `GET /api/catalog` | სრული დაკავშირებული კატალოგი, gzip და ETag ქეშით |
| `GET /api/catalog/meta` | დაფარვა, წყაროები, ქვეყნების რაოდენობები |
| `GET /api/institutions?q=&countryCode=&region=&page=&limit=&hasPrograms=` | გვერდებად დაყოფილი დირექტორია; მაქსიმუმ 100 ჩანაწერი |
| `GET /api/institutions/:id` | დაწესებულება და მასთან დაკავშირებული პროგრამები |
| `GET /api/programs` | ოფიციალური პროგრამების სია |
| `POST /api/recommendations` | კანონიკური პროგრამების შეფასება პროფილის მიხედვით, იგივე წესებით, რაც ბრაუზერში |
| `GET /api/auth/status` | ანგარიშების საცავის მზადყოფნა და მხარდაჭერილი როლები |
| `POST /api/auth/register`, `POST /api/auth/login` | ანგარიშის შექმნა / შესვლა ქუქი სესიით |
| `GET /api/auth/me`, `POST /api/auth/logout` | მიმდინარე სესია / სესიის გაუქმება |
| `GET/PUT /api/user/profile` | საკუთარი პროფილი და ფავორიტები |
| `GET/PUT /api/student/profile`, `GET/PUT /api/advisor/profile` | როლით დაცული საკუთარი პროფილები |

`GET /api/universities` შენარჩუნებულია თავსებადობისთვის და აბრუნებს რეალურ დაწესებულებებს. ძველი პროგრამის მსგავსი `price/matchScore/degree` ველები უნივერსიტეტის დონეზე აღარ არსებობს.

ფავორიტები ინახება ბრაუზერში და ავტორიზაციისას სინქრონდება ანგარიშთან. უნივერსიტეტებისა და პროგრამების ID-ები განსხვავდება; შედარებისას ტიპები არ აირევა. PDF ფაილები დროებით ინახება გახსნილ გვერდში; განახლება/გასვლა არჩეულ დოკუმენტებს ასუფთავებს.

ფოტოები `assets/`-ში საილუსტრაციოა. ვიზუალური სურათები `design-preview/`-ში შექმნილია ინტერფეისის შემოწმებისას; მიმდინარე კატალოგის მაგალითებია `worldwide-catalog-*` და `real-advisor-*`.
