# სტუდენტისა და მრჩევლის ანგარიშები

ავტორიზაცია იყენებს მუდმივ SQLite საცავს და სერვერის მიერ მართვად სესიებს. უნივერსიტეტების საჯარო კატალოგი ავტორიზაციისგან დამოუკიდებლად მუშაობს.

## გაშვება და საცავი

საჭიროა Node.js 24 ან სხვა გარემო, რომელსაც `node:sqlite` აქვს. ცალკე SQLite სერვერის ინსტალაცია საჭირო არ არის.

```powershell
npm.cmd install
npm.cmd start
```

გახსენით საიტი სერვერის მისამართიდან, ჩვეულებრივ **http://localhost:3000**. `index.html`-ის პირდაპირ ფაილად გახსნა რეალური სესიისთვის განკუთვნილი არ არის.

კონფიგურაცია `Server/.env`-ში:

| პარამეტრი | დანიშნულება |
| --- | --- |
| `AUTH_DB_DRIVER=sqlite` | ანგარიშების საცავის ამჟამად მხარდაჭერილი პროვაიდერი |
| `AUTH_DB_PATH` | SQLite ფაილის მდებარეობა; არ მოათავსოთ საჯარო სტატიკური ფაილების საქაღალდეში |

ამ ვერსიაში ჩვეულებრივი სესიის ვადა ფიქსირებულია **12 საათზე**, ხოლო „დამიმახსოვრე“ სესიისა — **30 დღეზე**. ეს ვადები გარემოს ცვლადებით არ იცვლება.

SQLite არჩეულია ცხადად. სერვერმა ერთი მოთხოვნისას MongoDB და მეორისას SQLite ჩუმად არ უნდა გამოიყენოს — ეს ორ სხვადასხვა ანგარიშების ბაზას შექმნიდა. ძველი MongoDB-ის ანგარიშები ავტომატურად არ მიგრირდება და ძველი მონაცემები არ იშლება.

SQLite ფაილი, მისი WAL/SHM დამხმარე ფაილები და სხვა საიდუმლო/სესიის რესურსები ვერსიების საცავში არ უნდა მოხვდეს. რეალურ გარემოში შეინახეთ მონაცემთა ბაზა შეზღუდული წვდომით და სარეზერვო ასლებით. მოქმედი WAL ბაზის სარეზერვო ასლისთვის გამოიყენეთ SQLite-ის შესაბამისი backup მექანიზმი ან ასლის შექმნამდე გააჩერეთ მწერალი პროცესი.

## რეგისტრაცია

ორივე როლისთვის საჭიროა სახელი, მოქმედი ელფოსტა, ტელეფონი, პაროლი, პაროლის დადასტურება და პირობებზე თანხმობა. ელფოსტა იწმინდება გარე ჰარეებისგან და ინახება პატარა ასოებით; უნიკალურობა მოწმდება მონაცემთა ბაზაშიც. წერტილები და `+alias` ნაწილები არ იშლება.

პაროლს სჭირდება მინიმუმ 10 სიმბოლო, მინიმუმ ერთი ასო და ერთი ციფრი. bcrypt-ის უხმო მოჭრის თავიდან ასაცილებლად მაქსიმუმია **72 UTF-8 ბაიტი**; მრავალბაიტიანი სიმბოლოები შეიძლება ერთზე მეტ ბაიტს იკავებდეს. სერვერი პაროლს ჰეშავს და არასდროს აბრუნებს პასუხში.

- **სტუდენტი** მიუთითებს განათლების დონეს, მოქალაქეობასა და დასრულების წელს. საკუთარი პროფილი და ფავორიტები მხოლოდ ამ ანგარიშის სესიით იცვლება.
- **მრჩეველი** მიუთითებს ორგანიზაციას, პოზიციას, სურვილისამებრ ვებსაიტს/აღწერასა და სპეციალიზაციებს. რეგისტრაციის შემდეგ შემოწმების სტატუსია `pending`.

მრჩევლად რეგისტრაცია არ ნიშნავს ორგანიზაციის ვინაობის დადასტურებას. მომხმარებელი საკუთარი როლით ვერ დაადასტურებს თავს, ვერ მიიღებს ადმინისტრატორის სტატუსს და ვერ ნახავს სტუდენტების პირად მონაცემებს. ადმინისტრატორის მიერ შემოწმების ცალკე პროცესი ამ ანგარიშის შექმნის ფუნქციის ნაწილი არ არის.

წარმატებული რეგისტრაცია ავტომატურად ქმნის სესიას. რეალური ელფოსტის მისამართით რეგისტრაცია მისამართის მფლობელობის შემოწმებას არ უდრის; ელფოსტის დადასტურებისა და პაროლის აღდგენის წერილების ცალკე ნაკადი ამ ეტაპზე არ არის დანერგილი.

## სესია და წვდომა

სესიის cookie არის `globaledu_session`, `HttpOnly`, `SameSite=Lax`, `Path=/`. production HTTPS გარემოში მას უნდა ჰქონდეს `Secure` ატრიბუტიც. სესიის ნედლი ტოკენი JSON პასუხში არ ბრუნდება და JavaScript-ს მისი წაკითხვა არ სჭირდება.

სერვერი ანგარიშის ვინაობასა და როლს ამოწმებს მონაცემთა ბაზიდან. ბრაუზერში შენახული სახელის ან როლის შეცვლა უფლებას არ ცვლის. `/auth/me` აღადგენს სერვერის მიმდინარე პროფილს; გასვლა სესიას სერვერზეც აუქმებს და cookie-ს ასუფთავებს.

ანგარიშის ცვლილებებისას მოწმდება მოთხოვნის Origin. უცხო საიტის Origin-ით შემოსული ცვლილება უარყოფილია. რეგისტრაციისა და შესვლის განმეორებული მცდელობები ექვემდებარება სიჩქარის შეზღუდვას. JSON სხეულის ზომაც შეზღუდულია.

## API

ყველა ქვემოთ მითითებულ მარშრუტს წინ უძღვის `/api`:

| მარშრუტი | შედეგი |
| --- | --- |
| `GET /auth/status` | `{provider:'sqlite',ready:true}` საიდუმლოებისა და ფაილის გზების გარეშე |
| `POST /auth/register` | ქმნის სტუდენტს ან მრჩეველს, აბრუნებს `201 {user,message}` და სესიის cookie-ს |
| `POST /auth/login` | ამოწმებს ელფოსტას/პაროლს; სურვილისამებრ `rememberMe:true`; აბრუნებს `{user}` და cookie-ს |
| `GET /auth/me` | სერვერის მიერ დადასტურებული მიმდინარე `{user}` |
| `POST /auth/logout` | აუქმებს მიმდინარე სესიას და cookie-ს |
| `GET /user/profile` | მიმდინარე ანგარიშის `{user}` |
| `PUT /user/profile` | ცვლის მხოლოდ დაშვებულ საკუთარ საერთო ველებსა და საკუთარ როლის პროფილს |
| `GET/PUT /student/profile` | მხოლოდ სტუდენტის როლისთვის; PUT სხეული `{studentProfile:{...}}` |
| `GET/PUT /advisor/profile` | მხოლოდ მრჩევლის როლისთვის; PUT სხეული `{advisorProfile:{...}}` |

რეგისტრაციის საერთო სხეულის მაგალითი:

```json
{
  "name": "Student Example",
  "email": "student@example.com",
  "phone": "+995555123456",
  "password": "StudentPass123",
  "passwordConfirm": "StudentPass123",
  "role": "student",
  "termsAccepted": true,
  "studentProfile": {
    "educationLevel": "bachelor",
    "citizenshipCode": "GE",
    "graduationYear": 2027
  }
}
```

ეს მხოლოდ დოკუმენტაციის მაგალითია; არ შექმნათ რეალური ანგარიში გაზიარებული მაგალითის პაროლით.

საერთო პროფილის განახლებაში დაშვებულია სახელი, ტელეფონი, ფავორიტები და საკუთარი როლის შესაბამისი ჩაშენებული პროფილი. ფავორიტების ზღვარია 200 ჩანაწერი. `role`, `verificationStatus`, სხვა მომხმარებლის `id`, პაროლი/ჰეში და მსგავსი პრივილეგირებული ველები ამ მარშრუტით არ იცვლება; აკრძალული ველები იწვევს `400` პასუხს.

სტატუსები: `400` — არავალიდური მონაცემი; `401` — არარსებული/არასწორი/ვადაგასული სესია ან არასწორი შესვლა; `403` — სხვა როლის რესურსი ან უცხო Origin; `409` — უკვე გამოყენებული ელფოსტა; `429` — მცდელობების ლიმიტი. ავტორიზაციის პასუხებში არ უნდა მოხვდეს პაროლის ჰეში, ნედლი სესიის ტოკენი ან მონაცემთა ბაზის შიდა დეტალები.

## შემოწმება

```powershell
node --test tests/auth.test.js
```

ტესტები იყენებს ნამდვილ SQLite in-memory საცავს და დროებით ფაილს შენახვის/ხელახლა გახსნის შესამოწმებლად. ისინი არ წერს რეალურ ანგარიშების ბაზაში და არ მოითხოვს MongoDB-ს ან გარე სერვისს.
