## მონაცემების განახლება

`.github/workflows/catalog-refresh.yml` ამზადებს გაშვებას ყოველ 6 საათში, UTC **00:17, 06:17, 12:17, 18:17** (თბილისი **04:17, 10:17, 16:17, 22:17**). შეიძლება ხელით გაეშვას Actions → Refresh university and programme catalogue → Run workflow.

ჯაჭვი: წყაროს პოლიტიკის შემოწმება → Hipo დირექტორია → რეგისტრირებული DAAD/ევროპის პროვაიდერები → მსოფლიოს კონფიგურირებული ოფიციალური წყაროები → სრული ვალიდაცია/ტესტები → Git commit → Vercel-ის განახლება. ჰოსტინგი რჩება Vercel-ზე და ანგარიში Supabase-ში.

წყაროს შეცდომა ინარჩუნებს მის წინა ჩანაწერებს. robots შეზღუდვა არ გადაილახება. საერთო ვალიდაციის შეცდომა აბრუნებს მონაცემების წინა მდგომარეობას; არასწორი განახლება არ ქვეყნდება. ახალი main commit-ის აღმოჩენისას workflow არ ასრულებს force push-ს.

`Server/data/catalog-refresh-status.json` განასხვავებს მცდელობას, წარმატებულ/ნაწილობრივ შედეგსა და წარუმატებლობას. საჯარო `/api/catalog/refresh-status` არ აბრუნებს შიდა დეტალებს. გახსნილი საიტი სტატუსს ათ წუთში ერთხელ ამოწმებს და ახალი გამოქვეყნებული ვერსიის არსებობისას კატალოგს ხელახლა კითხულობს.
