# Render-ზე გადატანა

მომზადებულია უფასო Web Service-ის `render.yaml`. ბაზა რჩება არსებულ Supabase-ში; ანგარიშების ხელახალი მიგრაცია, ცხრილების შექმნა ან მომხმარებლების პაროლების შეცვლა საჭირო არ არის.

## მფლობელის ნაბიჯები

ავტომატური გამართვისთვის: Render-ის **Account Settings → API Keys → Create API key**-ში შექმენი ამ workspace-ზე სერვისის შექმნის, გარემოს ცვლადების მართვისა და deployment-ის უფლების მქონე დროებითი გასაღები. შეინახე მხოლოდ ლოკალურ `Server/.env`-ში `RENDER_API_KEY=...` სახელით და მომწერე „შევინახე“. გასაღები არ გააგზავნო ჩატში. ეს ადმინისტრაციული გასაღები არ უნდა გადავიდეს ჰოსტინგის runtime გარემოში. გადატანის შემდეგ მისი გაუქმება შეგიძლია. მხოლოდ GitHub-ით შესვლა აგენტს Render API-ზე წვდომას არ აძლევს.

ქვემოთ ალტერნატიული, ხელით Blueprint-ის შექმნის ნაბიჯებია:

1. შედი https://dashboard.render.com/ GitHub-ით და მიეცი Render-ს მხოლოდ `Giorgikatamadze3/GlobalEduAI` რეპოზიტორიაზე წვდომა.
2. აირჩიე **New → Blueprint**, ეს რეპოზიტორია და `main` ბრანჩი. Blueprint ფაილია `render.yaml`. გადაამოწმე, რომ სერვისის პაკეტია **Free** და ფასი **$0**.
3. მოთხოვნილი სერვერული Environment Variables შეავსე პირადად, არსებული production კონფიგურაციიდან:
   - `SUPABASE_DATABASE_URL`: არსებული Supabase კავშირი. IPv4-ისთვის გამოიყენე Supabase-ის **Session pooler** URL, თუ direct კავშირი IPv6-ს მოითხოვს. სხვა URL-ზე გადასვლისას მომხმარებლის სახელიც Supabase Connect ფანჯრიდან გადაიღე; პაროლი იგივე ბაზისაა.
   - `SUPABASE_DB_CA_CERT`: Supabase-ის ოფიციალური CA PEM სერტიფიკატი; შეინარჩუნე რეალური ხაზები ან არსებული `\n` ფორმატი. TLS შემოწმება არ გამორთო.
   - `ADMIN_ACCOUNT_IDS`: Vercel Production-ში შენახული არსებული ადმინისტრატორის UUID. ელფოსტით ახალ უფლებას ნუ გასცემ.
4. სურვილისამებრ დაამატე არსებული `OPENAI_API_KEY` და `OPENAI_MODEL`. გასაღები მხოლოდ Render Environment-ში შეინახე, არა GitHub-ში ან ჩატში.
5. გაუშვი Blueprint. დასრულებისას მომაწოდე მხოლოდ საჯარო `https://….onrender.com` მისამართი, რომ ხელმისაწვდომობა და API შევამოწმო.

## უკვე გაშვებული globaleduai.onrender.com-ის გამართვა

მფლობელისთვის მომზადებულია ლოკალური `Server/.env.render` ფაილი, რომელიც `.gitignore`-ით Git-იდან გამორიცხულია. ის შეიცავს მხოლოდ ამ Render სერვისისთვის საჭირო Supabase კავშირს, CA-ს, არსებულ ადმინისტრატორის ID-ს, ახალ საჯარო მისამართებსა და არჩევით AI კონფიგურაციას. გასაღებების მნიშვნელობები არც ტერმინალში და არც დოკუმენტაციაში არ გამოქვეყნებულა.

Render-ში გახსენი **GlobalEduAI → Environment → Add from .env**, ჩასვი ამ ფაილის შიგთავსი და აირჩიე **Save, rebuild, and deploy**. ეს არ არის Secret File-ის ატვირთვა: მნიშვნელობები უნდა დაემატოს Environment Variables-ში. კოდში SQLite fallback-ის დაბლოკვა GitHub-ზე ცალკე აიტვირთა; ახალი deploy-ის შემდეგ `/api/auth/status`-მა უნდა დააბრუნოს `provider: postgres, ready: true`. ეს მხოლოდ კავშირის შემოწმებაა; სტუდენტის შესვლა და ადმინისტრატორის უფლება დამატებით მოწმდება. `.env.render`-ის შიგთავსი ჩატში ან სქრინში არ გამოაჩინო.

## ავტომატური გამართვა

- Node.js 24, `npm ci --include=dev && npm run check`, `npm start`.
- PostgreSQL driver და Supabase private schema; მონაცემები ადგილობრივ ფაილებში არ ინახება.
- სერვერი Render-ის `PORT`-ს უსმენს `0.0.0.0` მისამართზე.
- HTTPS proxy-ის გათვალისწინება აუცილებელია უსაფრთხო cookie-ებისა და Origin შემოწმებისთვის; Render-ზე ეს ჩართულია.
- `/healthz` მსუბუქი ჯანმრთელობის შემოწმებაა, ბაზის მოთხოვნის გარეშე. ის მხოლოდ პროცესის ხელმისაწვდომობას ამოწმებს.
- საჯარო canonical/sitemap მისამართი Render-ის `RENDER_EXTERNAL_URL`-იდან ივსება. საკუთარი დომენის დამატებისას მიუთითე `PUBLIC_SITE_URL` ახალი HTTPS origin-ით.
- **არ გადაიტანო ძველი Vercel მისამართი** `PUBLIC_SITE_URL` ან `BILLING_PUBLIC_ORIGIN` მნიშვნელობებში. დატოვე unset, თუ საკუთარი დომენი არ გაქვს.
- **არ გადაიტანო** `VERCEL`, `SUPABASE_MIGRATION_ACTION`, `DATA_MIGRATION_READ_ONLY`, სატესტო ბაზის URL-ები ან ერთჯერადი მიგრაციის პარამეტრები. Runtime-ს direct migration URL არ სჭირდება.
- ანგარიშების მონაცემები საერთო Supabase ბაზაშია, თუმცა ახალ დომენზე თავიდან შესვლაა საჭირო: ძველი დომენის cookie ახალ დომენს არ გადაეცემა.
- GitHub-ის ექვსსაათიანი კატალოგის განახლება უცვლელად მუშაობს. Render სერვისზე გადაამოწმე **Auto-Deploy → On Commit**, რათა მონაცემთა ახალი commit-ები გამოქვეყნდეს.

## ცალკე დასასრულებელი პუნქტები

- Render ანგარიშთან წვდომა ამ სესიაში ჯერ არ არის; კოდის მომზადება არ ნიშნავს, რომ Render-ზე საიტი უკვე გამოქვეყნდა.
- პირველი ხელით deploy-ის ლოგში დაფიქსირდა `ანგარიშები: sqlite`. ეს Supabase-ზე წარმატებულ გადატანას არ ნიშნავს. Render-ის **Environment**-ში აუცილებელია `DATABASE_PROVIDER=supabase`, `AUTH_DB_DRIVER=postgres`, არსებული `SUPABASE_DATABASE_URL`, `SUPABASE_DB_CA_CERT` და `ADMIN_ACCOUNT_IDS`. ახალი კოდი Render-ზე არც ანგარიშებისთვის, არც CMS-ისთვის და არც billing-ისთვის ადგილობრივ SQLite საცავს აღარ გამოიყენებს; გაუმართავი ბაზის შემთხვევაში დაცული ფუნქციები მიუწვდომელი იქნება, სანამ Supabase კავშირი არ გასწორდება.
- საიტის გახსნის შემდეგ შესამოწმებელია სტუდენტის შესვლა, ადმინისტრატორის უფლებები და საკუთარი პროფილის შენახვა. production-ზე დროებითი ანგარიშის შექმნისას წაშალე ტესტის შემდეგ.
- Vercel-ის billing cron Render-ზე ავტომატურად არ გადადის. ფასიანი გადახდები გამორთულია. რეალური billing-ის ჩართვამდე საჭიროა დაცული scheduler-ის გადატანა და ახალი callback/return URL-ების შემოწმება; მხოლოდ Blueprint cron-ს არ ქმნის.
- Free სერვერი 15 წუთის უმოქმედობის შემდეგ იძინებს; გაღვიძებას დაახლოებით წუთი სჭირდება. უფასო რესურსებს აქვს ლიმიტები; 24/7 სწრაფი გაშვება გარანტირებული არ არის.
- Render Free ბლოკავს SMTP პორტებს 25/465/587. წინა SMTP ინსტრუქცია ამ ჰოსტზე საკმარისი არ არის: პაროლის აღდგენის წერილებისთვის საჭიროა HTTPS transactional email API-ის ინტეგრაცია და დადასტურებული გამგზავნი. აღდგენის წერილები მანამდე გამორთულია; საკუთარი პაროლის შეცვლა მუშაობს.
- საჯარო Render სერვისის შემოწმებამდე ძველ Vercel პროექტს და Supabase-ის ბაზას ნუ წაშლი.
